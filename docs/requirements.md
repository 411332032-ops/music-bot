# 需求說明

## 這是什麼
一個在我自己電腦上執行的 Discord agent。只要它開著，我 Discord Server 裡指定頻道的任何人傳一張音樂專輯封面或歌詞照片進來，它就會辨識專輯名稱、歌手、曲風、OCR 擷取歌詞、建檔，再回覆上傳者。agent 關掉就不處理。

## 誰會用
我自己的 Discord Server 裡、那個指定頻道的任何人，用手機或電腦都可以傳。

## 使用的流程
1. 有人在頻道裡傳一張音樂專輯封面或歌詞照片
2. agent 收到，先回一個「處理中」的提示（如 ⏳）
3. agent 判斷：是不是音樂相關圖片（專輯封面/歌詞）、專輯/歌曲名稱、歌手/樂團、曲風估算、識別歌詞/文字內容
4. agent 把結果記下來、把照片存起來
5. agent 回覆上傳者這張圖片的辨識結果，並附上「當日已紀錄音樂數」的總數

## 要記錄的內容（存成一個可以一直往下加的 Excel 檔）
- 日期時間
- 上傳者
- 圖片類型（專輯封面 / 歌詞手稿 / 其他非音樂）
- 專輯/歌曲名稱
- 歌手/樂團
- 曲風估算
- 辨識歌詞/文字內容
- 當日已紀錄音樂數
- 照片存放位置

照片另外存進一個資料夾，檔名用「YYYY-MM-DD hh-mm-ss + 專輯/歌曲名稱簡稱」（連字號 `-`，若撞名則自動加上 `-2`）。

## 不是音樂相關圖片的時候
一樣要回覆上傳者「你傳的不是音樂封面或歌詞，是某某東西」，用 agent 判斷出來的東西說明。這種照片一樣要建檔、一樣要存，只是圖片類型寫「非音樂相關」，專輯名稱與歌詞欄位註明其真實內容說明。

## 畫面上 / 回覆上要有
- 收到時先有「處理中」的提示（如 ⏳ 貼圖）
- 處理完回覆：是不是音樂圖片、圖片類型、專輯/歌曲名稱、歌手/樂團、曲風、辨識歌詞內容、當日已紀錄音樂總數

## 不需要的
- 註冊、登入
- 長時間、大規模的雲端服務（這就是一支開著才會動的本機程式）
- 外部權威音樂 API 比對（如 Discogs / Spotify API，本版本純靠 LLM 語意與視覺推論）
- 分使用者（User ID）計算個人統計（當日累計數為該頻道內所有人上傳的總合）

## 技術上我知道的
- 用 Python 3.12 + uv（課前已經裝好；實務上也可以用別的語言，這裡先固定）
- 照片用 `claude -p` 在我這台電腦上處理
- Discord 用 Gateway（bot）模式，不需要 ngrok
- 紀錄存成一個可以持續往下加（append 模式）的 Excel 檔
- 設定放在 `.env`：`DISCORD_TOKEN`、`CHANNEL_ID`、`CLAUDE_MODEL`、`DATA_DIR`

## 做事的順序
1. 先把 agent 做好，所有防護都開著（包含 4 段標註 `# ==== 防護 N ... 開始/結束 ====` 的防護），自己測到正常
2. 之後（上課時）再把防護全部關掉做對照
